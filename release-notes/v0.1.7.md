# mita v0.1.7

This Windows release improves the bundled literature extraction skill, switches auto-memory to a global per-user store with relevance-based recall, and speeds up the update startup check.

## Literature extraction

- Added `references/shard-worker.md` as the single source of truth for literature-field-extraction subagents. The main agent now points subagents to this file instead of retelling the rules in each task prompt, eliminating omission drift.
- Pinned five anti-hallucination rules for subagents: serial per-PDF processing (no batch-read-then-batch-write), table language follows the source document, verbatim author / corresponding author / PI, no fabricated content, and leave unverifiable fields blank with an issue.
- Registered the new reference file in `SKILL_FILES` and updated `SKILL.md` / `workflow.md` to route subagent prompts through it.

## Memory

- Enabled relevance-based memory recall by default. Each user prompt triggers a prefetch that uses a selector over memory-file frontmatter to surface up to 5 relevant memories as attachments, instead of injecting the full `MEMORY.md` index into the system prompt. The previous `tengu_moth_copse` GrowthBook gate (default off) is replaced by a local `isRelevanceRecallEnabled()` helper (default on).
- Routed the desktop Memory Settings UI to the global auto-memory directory. The server memory API now resolves all paths through `getAutoMemPath()` instead of the hardcoded `~/.claude/projects/<id>/memory/` layout, so the UI sees and edits the same global memories the CLI runtime writes. `projectId` is still accepted on `/files` and `/file` for backward compatibility but no longer affects the directory.
- Deleted ~250 lines of per-project label resolution helpers from the memory API that only served the old per-project listing.
- Updated i18n copy in zh / en / zh-TW / kr / jp: "Project Memory" → "Global Memory", description paths updated to `~/.claude/memory/`, slash command description drops "project".

## Updates

- Shortened the auto-update startup delay from 5 seconds to 1.5 seconds so users see update prompts sooner after launch. The download / verify / install flow is unchanged: electron-updater still verifies the package before the install prompt appears, and dismissed versions do not re-prompt on the next launch.

## Packaging

- Desktop release artifacts are Windows-only for this build.
